How hardware adds numbers
At the lowest level, CPUs use full adders.
A 1-bit full adder takes:
2 input bits (A, B)
1 carry-in (Cin)
And produces:
Sum
Carry-out
Logic:
Sum   = A ⊕ B ⊕ Cin
Carry = (A & B) | (Cin & (A ⊕ B))
👉 Chain 32 of these → you get a 32-bit adder

⊕ - XOR gate - if number of 1 is odd then result will be 1 else 0
& - bitwise AND - if both are one then result is 1 else 0
| - bitwise OR - if both are zero then 0 else 1
What a full adder does
A 1-bit full adder takes three inputs:
A (bit from first number)
B (bit from second number)
Cin (carry from previous/less-significant bit)
Outputs:
Sum (result bit at this position)
Carry (goes to the next higher bit)

Left shift:
    shifting bits to left and fill zero at right
n << 1
    1010 << 1
    10100   -> 20
n << 2
    1010 << 2
    101000  -> 40
General left shift rule
    n << k
        n * (2^k)   -   if result overflows then ignores
    10 << 2
        10 * (2^2)  -> 40
Left most bit is the sign bit, in left shift we are shifting bits left and adding zero at right, so no need to handle sign bit.
if left most bit is 0 and one bit before left most is 1 then if we do left shift once then the positive number will automatically becomes negative.
for 2147483647, binary is 01111111111111111111111111111111 and if we shit it to one time left
    11111111111111111111111111111110 - here left most bit is 1, so this is negative and its value is -2
    2's complement of -2 is 11111111111111111111111111111110
    this is why max value of integer is 2147483647 and also this is the reason there is no <<< - sign specific operator in left shift
    we are clear that we need to add 0 at right, sign bit is automatically handled.
    In right shift scenario we will move bits right, so left most bit will be empty and we need to fill it, 
    if we fill it with 0 then result will be positive and if we fill with 1 then resutl will be negative.
    thats is why left shift has no <<< and right shift has >>>.

Right shift operator:
>>	Signed right shift (arithmetic)	Preserves sign
>>>	Unsigned right shift (logical)	Fills with 0

Signed right shift >>:
    n >> k 
        here n is right shifted k times then left bits are filled with sign bits. if we shift 3 times then left most 3 bits are filled with sign bits.(1 for negative and 0 for positive)
Original:   11111000   (-8)
Shift >> 2:
Step 1 →    11111100
Step 2 →    11111110
Final:
11111110 (-2)
👉 Leftmost 2 bits filled with 1

Original:   00001000   (8)
Shift >> 2:
Step 1 →    00000100
Step 2 →    00000010
Final:
00000010 (2)
👉 Leftmost 2 bits filled with 0

n>>1 - it will work like n divide by 2.
n>>k - it will work like n divide by 2^k.
    x >> k = x / (2^k)

Unsigned right shift (>>>)
    Shift bits to the right and Fill leftmost bits with 0.
int x = -8;
int y = x >>> 1;
Binary:
x = 11111111 11111111 11111111 11111000
After shift:
01111111 11111111 11111111 11111100
Result:
2147483644

Shift count is masked:
x >> n   → n % 32
So:
x >> 33 == x >> 1
